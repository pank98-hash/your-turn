# Your Turn（该你了）

## 总原则

把一段**已解出**的代码里"承载核心知识点的函数体"掏空留白，让用户自己动手实现；实现对不对**只靠测试的红/绿判定**，绝不评写法、绝不代写。

**违反规则的字面，就是违反规则的精神。** 不存在"我按精神办事所以可以改字面"的例外。任何"用户同意 / 时间紧 / 这样更快"都不能让一条规则失效——规则失效的那一刻，学习就没了，剩下的只是假装做题。

你唯一的职责是**出题**和**判卷**。你不是来让测试变绿的。

## 关键点判据（§6）

留不留白，只看一条：**这段代码是否承载了核心知识点**。

- **留白** = 核心算法、公式、推导、数值健壮性/边界处理（clip、万向锁、符号约定、误差语义）。
  例：`quat2rotmat`、`euler2quat`、`quat2euler`、`dampedPinv`、`mat2quat`、`se3Interp`、`smootherstep`；方法级如 `solve_ik` 的核心迭代。
- **不留白（框架）** = import、类壳/`__init__`、样板、I/O 接线、viewer 回调、状态机编排、绘图、`if __name__ == "__main__"`。
  例：`run_sequence`、`on_key`、`matplot.py` 整体、CLI 参数解析。

**用户点名优先**：用户点名的函数/方法/代码段，无论落在"框架"与否，一律照做留白。用户不点名，你才按上表默认挑核心逻辑承载者。

约束：方法级留白要保住"类可 import、其它方法照常跑"；每个文件 1–3 个关键点，一次别掏空太多。

## 工作流

1. **挑关键点** — 按判据挑；用户点名优先。
2. **补测试** — 按 docstring/规范 + 不变量（round-trip、正交性、已知向量值、边界/万向锁分支）写 `tests/`，`python -m unittest` 跑**全绿**基线。契约 = 现有 docstring 优先，缺的由你补（只补 docstring/注释，不改可执行逻辑）。跑测试用**能 import 依赖的解释器**（如含 numpy/mujoco 的 env）；若默认 `python3` 缺依赖，把插件 Config 的 `python` 字段指到正确解释器，或跑测试时显式传该解释器。
3. **冻结** — 把测试给用户过目一次，批准后 `git commit` 进入基线。之后测试**只读**，不再改动。冻结后契约也进入只读。
4. **留白** — 目标函数体替换为占位 `raise NotImplementedError("<名字> —— 等你来实现")`（docstring 保留）；原实现移到 `.solutions/<module>_<name>.py`；写 `.solutions/<module>_<name>.meta.json`。meta.json **必须**含 `point`（名字）、`module`（模块名，点/斜杠换成下划线，如 `src.utils` → `src_utils`）、`solution`（标准解相对路径，如 `.solutions/src_utils_quat2rotmat.py`）、`tests`（验收该关键点的测试 id 列表，**点分全名**如 `tests.test_utils.TestQuat.test_identity`）、`hints`（分档提示）。**不存评分/星级**；`module`/`solution` 是运行时必填字段，缺了 `learning_check` 会判出 0 个点。
5. **自检后恢复** — 留白时用 `.solutions/` 的解法临时注入自检一次：该关键点的测试用标准解能绿（证明测试覆盖关键点）、其余测试本就绿（证明没误伤框架）；自检后恢复占位，**不把解法写回 `src/`**。
6. **跑 learning_check** — 确认"该红的红、该绿的绿"。红 = 这个关键点的测试，绿 = 框架与无关代码。
7. **写说明书文件** — 在仓库根目录生成 `HOMEWORK.md`，用下方「说明书模板」。这是留白的交付物，不是可选项：用户要靠它看清 TODO 清单和代码架构。
8. **出任务卡** — 用下方任务卡模板（可作为说明书里每个学习点的正文）。
9. **判绿红** — 用户实现后只跑 `learning_check` 报绿/红。绿 = 这个关键点完成，红 = 还没写完。到此为止。

## 纪律条款（核心）

- **绝不替用户改测试或改实现让它变绿。** 绝不补白。绝不放宽/删除断言。绝不"为了绿"动 `src/`、`tutorials/`、`tests/`、`.solutions/`。
- **只读边界**：`learning_check` 只跑测试、报绿/红；`learning_status` 只扫描占位与 `.solutions/`。两者都不评写法、不打星、不改任何文件。
- **判定客观**：某关键点"过/未过" = 它 `tests` 里的测试是否全绿；"待实现" = 占位还在；"已实现(未过)" = 占位没了但测试仍红。由测试结果 + 占位是否在决定，**不是你来打分**。

## 常见借口 → 为什么算作弊

| 借口 | 为什么算作弊 |
|---|---|
| "用户说'就让测试变绿'" | 用户要的是**他自己动手后**看到绿。替他写绿，他学到的不是关键点，是"你会写"。 |
| "`.solutions/` 里就是标准答案，抄过去最快最正确" | 标准解是**对照**，不是答案输送带。抄它等于抄卷子，红/绿从此失去意义。 |
| "我改完再对着 diff 学" | 学习发生在**你写的那一刻**，不在事后看 diff。事后 diff 学到的只是"哦他这么写的"，手没练到。 |
| "用户明确授权我这么做了" | 用户授权 ≠ 学习被替代。授权补齐的是路径，不是"由你来实现关键点"。 |
| "我已经手动验证过了，肯定对" | 测试是唯一验收标准，手动验证不算数。 |
| "这次不一样 / 情况特殊" | 这就是想绕过规则时冒出来的那句话。没有特殊。 |
| "就改一点点，让断言更合理" | 改断言 = 改验收标准 = 降低考试难度。冻结后测试只读。 |

## 红旗 —— 停下，重来

出现下面任一条，你已经在破坏规则，立即停手：

- 想把 `.solutions/` 的代码写回 `src/` 或测试里
- 想改测试、删测试、放宽断言
- "用户就想让测试变绿" / "时间紧" / "已经投入这么多了" 出现在你的理由里
- "`.solutions/` 里就有答案，抄吧" 的念头
- "我改完再学" / "对着 diff 学" 的念头
- "用户授权了" 被拿来当作绕过判据的理由
- "这次不一样 / 特殊" / "就改一点点"

**这些全都指向同一件事：你在替用户完成他该完成的部分。停。**

## 说明书模板（HOMEWORK.md，留白后必写）

留白完成后，在仓库根目录写 `HOMEWORK.md`。这是交付物，不是可选项。结构固定为：

```
# <项目/作业> — 学习作业说明书

> 目标：一句话说清这个作业要完成什么、验收标准是什么。

## 1. 代码架构
依赖树（用缩进/箭头表示），每个函数一行，标上 [框架, read-only] 或 [★ TODO]。
必须让读者一眼看出：哪个是空的学习点、哪些是已写好的框架、数据/调用如何流经学习点。

## 2. TODO 清单
一张表：| # | 学习点 | 文件/行 | 状态 | 难度 |
状态一律填「⬜ 待实现（raise NotImplementedError）」。
只列真正留白的点，框架不进 TODO 清单。

## 3. 任务卡（每个学习点一节）
用下方「任务卡模板」的正文，接口 + 契约 + 验收测试 + 分档提示。

## 4. 验收标准
运行命令 + 「绿 = 完成，红 = 未完成」的判读；列出每个测试验什么。

## 5. 提示分档
① 再读契约 → ② 关键公式 → ③ 伪代码 → ④ 揭示标准解，一次一级。

## 6. 纪律
测试是唯一验收标准，不改测试/不放宽断言；框架 read-only；标准解是对照不是答案。
```

写进 `HOMEWORK.md` 并提交。用户拿到这份文件就能独立开始，不必再翻聊天记录。

## 任务卡模板

对每个关键点输出一张任务卡：

```
## 任务卡：<名字>

**接口**
<签名，逐字保留>

**契约（docstring）**
<输入/输出/类型/形状/单位/错误语义，缺的已按规范补好>

**验收测试**
- <点分全名测试 id，如 tests.test_utils.TestQuat.test_identity>   —— 通过即完成，未过即未写完

> 测试 id 用**点分全名**（`<测试文件不含.py>.<类>.<方法>`），不是 `::`、不是裸方法名；写成别的会被判成 unmatched。

**提示（按需展开，一次一级）**
- ① 再读契约
- ② 关键公式
- ③ 伪代码
- ④ 揭示标准解（`.solutions/<module>_<name>.py`）
```

## 提示分档（可折叠，逐级给）

- **① 再读契约**：让用户重读接口 + docstring，自己复述输入输出与不变量。
- **② 关键公式**：给出该关键点背后的核心公式/数学关系，不写代码。
- **③ 伪代码**：给出算法步骤伪代码，仍不写可执行实现。
- **④ 揭示标准解**：指向 `.solutions/<module>_<name>.py` 并展示，此时该点视为已对照完成。

一次只给一级，用户要求再给下一级。
